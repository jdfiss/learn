一、知識點逐個講解

1.1 Workspace：為什麼需要一個「工作區」

它解決什麼問題

ROS2 官方裝好之後，所有東西都在 /opt/ros/humble，那是唯讀的系統目錄。你自己寫的程式不能塞進去（也不該塞）。但你自己寫的節點又必須讓 ros2 run、ros2 launch 找得到。Workspace 就是「你自己的、可寫的、能被 ROS 工具鏈認得的第二個地盤」。

白話解釋 + 比喻

把 /opt/ros/humble 想成學校的公用圖書館——書很多，但你不能在上面寫字。Workspace 是你自己的書桌，你在書桌上寫的筆記，只要在「登記簿」上登記過（＝ source setup.bash），別人查資料時就會先查你的書桌、查不到才去圖書館。這個「先查書桌再查圖書館」的順序，就是後面要講的 overlay 蓋在 underlay 上。

三個目錄的分工

目錄誰產生裡面是什麼可以刪嗎
src/你原始碼。唯一你該手動編輯的地方不行，刪了就沒了
build/colcon編譯中間產物、CMake 快取、egg-info可以，且卡關時常常該刪
install/colcon最終安裝結果：可執行檔、setup.bash、share/ 裡的 launch 與 msg可以，重 build 會回來
log/colcon每次 build 的完整輸出，除錯神器可以
常見誤解：「我改了 src 裡的 .py，為什麼 ros2 run 跑的還是舊的？」 因為 ros2 run 執行的是 install/ 底下那份複製品，不是你剛改的 src/。除非你用 --symlink-install（下面會講），否則每次改 Python 都要重 build。這是新手第一週最常鬼打牆的一題。

1.2 Package：ROS2 的最小發佈單位

它解決什麼問題

你不會希望「一個超大資料夾裝全部程式」。Package 是 ROS2 的模組單位：一個 package = 一組相關的節點 + 它的相依宣告 + 它的建置規則。ros2 run <package> <executable> 這個指令的第一個參數就是 package 名。

Python package 一定要有的四樣東西

檔案作用白話
package.xmlROS 層級的身分證與相依宣告「我叫什麼、我需要誰、我用哪種建置系統」
setup.pyPython 層級的安裝腳本「哪些檔案要複製到 install/、哪個函式是可執行檔入口」
setup.cfg告訴 setuptools 執行檔要放哪放到 lib/<package>，這樣 ros2 run 才找得到
<pkg>/__init__.py讓資料夾成為 Python module沒有它，import 會失敗
ament_python vs ament_cmake 純 Python 節點 → ament_python（今天用這個）。要自訂 msg/srv、或有 C++ → ament_cmake（Day 4 會用）。自訂 msg 不能放在 ament_python 的 package 裡，這是 Day 4 的第一個坑，今天先記住。

1.3 setup.py 的 entry_points：ros2 run 到底在跑什麼

它解決什麼問題

ros2 run my_pkg talker 這句話，ROS2 是怎麼從 talker 這個字找到你的 Python 函式的？答案是 setup.py 裡的 entry_points。

entry_points={
    'console_scripts': [
        'talker = my_py_pkg.publisher_node:main',
    #    ^^^^^^   ^^^^^^^^^^ ^^^^^^^^^^^^^^^ ^^^^
    #    指令名     package名   .py 檔名(不含.py)  要呼叫的函式
    ],
},

build 時 setuptools 會在 install/my_py_pkg/lib/my_py_pkg/talker 生出一支小小的殼層腳本，內容大致是「import my_py_pkg.publisher_node，然後呼叫 main()」。ros2 run 就是去那個路徑找同名檔案來執行。

常見誤解：「executable 名字一定要跟 .py 檔名一樣」 不用。左邊的 talker 是你要打的指令名，右邊的 publisher_node 才是檔名，兩者可以完全不同。錯誤訊息 No executable found 十次有八次就是這行寫錯、或是改完沒重 build。

1.4 colcon build 到底做了什麼

它解決什麼問題

你的 workspace 裡可能有 10 個 package，彼此有相依關係（A 用到 B 的 msg）。colcon 的工作是：讀每個 package.xml 算出相依拓撲 → 決定編譯順序 → 依 build_type 呼叫對應的建置工具 → 把結果安裝到 install/ → 產生 setup.bash 環境腳本。

比喻

colcon 像工地的工頭：它自己不砌磚，但它看得懂圖（package.xml），知道「地基（B）要先做完才能蓋二樓（A）」，然後叫對的工班（setuptools 或 CMake）去做，最後驗收入庫。

三個你一定要會的參數

參數作用什麼時候用
--symlink-installinstall/ 裡放符號連結指回 src/，而不是複製寫 Python 時幾乎一定要加，改完不用重 build（新增檔案或改 setup.py 時仍要重 build）
--packages-select <pkg>只 build 指定的 packageworkspace 大時省時間
--event-handlers console_direct+把編譯輸出直接印在畫面上編譯錯誤看不出所以然時
鐵律：colcon build 一定要在 workspace 根目錄（~/ros2_ws）執行，不能在 src/ 裡面執行。 在 src/ 裡執行的話，colcon 會在 src/ 底下再生一組 build/install，之後整個環境會錯亂。真的做錯了：rm -rf src/build src/install src/log。

1.5 source setup.bash：underlay 與 overlay

它解決什麼問題

ROS2 的指令列工具（ros2 run、ros2 topic）是靠環境變數找東西的，不是靠掃描整台電腦。source setup.bash 就是把路徑寫進當前這個 shell 的環境變數。

它到底改了什麼

# source 之後可以自己看：
echo $AMENT_PREFIX_PATH     # ROS 找 package 的路徑清單
echo $PYTHONPATH            # Python import 找得到你的 module
echo $LD_LIBRARY_PATH       # C++ 動態函式庫路徑
echo $ROS_DISTRO            # humble
echo $ROS_DOMAIN_ID         # 同一區網互相隔離用（沒設就是 0）

比喻

underlay（/opt/ros/humble/setup.bash）＝地基那層樓；overlay（~/ros2_ws/install/setup.bash）＝蓋在上面那層。查詢時由上往下找，所以你 workspace 裡如果有一個跟官方同名的 package，你的會贏。順序不能反：先 source underlay，再 source overlay。

常見誤解：「我 source 過了啊，為什麼另一個終端機不認得？」 source 只影響執行它的那一個 shell。你開新分頁、新視窗、ssh 進來、或是用 VS Code 內建終端機，那都是全新的 shell，環境是乾淨的。每個新終端機都要重 source。想省事就寫進 ~/.bashrc（下面有指令），但要知道代價：以後你 build 壞掉時 bashrc 也會噴錯。

1.6 rclpy 節點的骨架：五行心法

每一支 rclpy 節點都長一樣，記住這五步就能默寫：

  1. rclpy.init()　→ 啟動 ROS2 通訊層（DDS middleware）
  2. node = MyNode()　→ 建節點，在 __init__ 裡建 publisher / subscriber / timer
  3. rclpy.spin(node)　→ 把控制權交給 ROS2，開始處理 callback，這行會卡住直到 Ctrl+C
  4. node.destroy_node()　→ 釋放資源
  5. rclpy.shutdown()　→ 關掉通訊層
常見誤解：「我在 main 裡寫個 while True 迴圈發訊息就好，幹嘛用 timer？」 可以，但你會發現Subscriber 收不到東西。因為 callback（包含 subscriber callback）只有在 rclpy.spin() 或 rclpy.spin_once() 執行時才會被處理。自己寫 while 迴圈等於把 ROS2 的事件迴圈餓死。正確做法：週期性動作用 create_timer，然後交給 spin。

二、可直接複製貼上的指令與程式碼

步驟 1：建 workspace 與 package

# --- 每個新終端機第一件事：source underlay ---
source /opt/ros/humble/setup.bash

# 建 workspace（ros2_ws 是慣例名稱，src 是 colcon 硬性規定的資料夾名）
mkdir -p ~/ros2_ws/src
cd ~/ros2_ws/src

# 建一個 ament_python package
# --node-name 會順便幫你生一個範例節點與 entry_point，第一次很好用
ros2 pkg create --build-type ament_python \
    --license Apache-2.0 \
    my_py_pkg

cd ~/ros2_ws
tree src -L 3      # 沒有 tree 就 sudo apt install tree

你應該看到：

src/my_py_pkg/
├── my_py_pkg/          <-- 你的 Python 程式放這裡（跟 package 同名，不是巧合）
│   └── __init__.py
├── resource/my_py_pkg  <-- ament 索引用的空檔，不要刪
├── test/
├── package.xml         <-- ROS 相依宣告
├── setup.cfg
└── setup.py            <-- entry_points 在這裡

步驟 2：Publisher 節點

# 檔案：~/ros2_ws/src/my_py_pkg/my_py_pkg/publisher_node.py
import rclpy
from rclpy.node import Node
from std_msgs.msg import String


class TalkerNode(Node):
    def __init__(self):
        # 'talker' 是節點名稱，會出現在 ros2 node list
        super().__init__('talker')

        # create_publisher(訊息型別, topic 名稱, QoS depth)
        # 10 = KEEP_LAST 佇列深度，訂閱者來不及收時最多留 10 筆
        self.pub_ = self.create_publisher(String, 'chatter', 10)

        self.counter_ = 0
        # 每 0.5 秒呼叫一次 timer_callback（2 Hz）
        self.timer_ = self.create_timer(0.5, self.timer_callback)

        # get_logger() 是 ROS2 的 print，會帶時間戳與節點名，
        # 而且能被 ros2 launch / rqt_console 收集，一律用它而不要用 print()
        self.get_logger().info('Talker 已啟動，發佈到 /chatter')

    def timer_callback(self):
        msg = String()                      # 建一個空訊息物件
        msg.data = f'hello ROS2 #{self.counter_}'   # 填 data 欄位
        self.pub_.publish(msg)              # 送出
        self.get_logger().info(f'發佈：{msg.data}')
        self.counter_ += 1


def main(args=None):
    rclpy.init(args=args)       # 1. 啟動通訊層
    node = TalkerNode()         # 2. 建節點
    try:
        rclpy.spin(node)        # 3. 交出控制權，直到 Ctrl+C
    except KeyboardInterrupt:
        pass
    finally:
        node.destroy_node()     # 4. 釋放
        rclpy.shutdown()        # 5. 關閉


if __name__ == '__main__':
    main()

步驟 3：Subscriber 節點

# 檔案：~/ros2_ws/src/my_py_pkg/my_py_pkg/subscriber_node.py
import rclpy
from rclpy.node import Node
from std_msgs.msg import String


class ListenerNode(Node):
    def __init__(self):
        super().__init__('listener')

        # create_subscription(型別, topic 名稱, callback 函式, QoS depth)
        # 注意 callback 不要加括號 —— 傳的是函式本身，不是呼叫結果
        self.sub_ = self.create_subscription(
            String, 'chatter', self.listener_callback, 10)

        self.get_logger().info('Listener 已啟動，訂閱 /chatter')

    def listener_callback(self, msg):
        # 每收到一筆訊息，ROS2 會自動幫你呼叫這個函式
        self.get_logger().info(f'收到：{msg.data}')


def main(args=None):
    rclpy.init(args=args)
    node = ListenerNode()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    finally:
        node.destroy_node()
        rclpy.shutdown()


if __name__ == '__main__':
    main()

五、🎓 助教筆記：學生今天最會卡的 5 個點

① Package 'my_py_pkg' not found

真正原因（依機率排序）：(a) 沒 source overlay；(b) 在錯誤的目錄 build，install/ 根本沒生出來；(c) build 其實失敗了但學生只看最後一行沒看到紅字。

診斷指令：

echo $AMENT_PREFIX_PATH | tr ':' '\n'   # 有沒有你的 ros2_ws/install？
ls ~/ros2_ws/install/                    # 有沒有 my_py_pkg 資料夾？
ros2 pkg list | grep my_py_pkg           # ROS 認不認得

解法：cd ~/ros2_ws && colcon build --symlink-install 然後開一個全新終端機再 source。叫學生開新終端機比叫他 source 更保險，因為舊 shell 可能有髒環境變數。

② No executable found

真正原因：entry_points 那行的四個欄位其中之一打錯——最常見是「檔名寫成 publisher_node.py（多了 .py）」或「冒號寫成點」。第二常見是改完 setup.py 沒重 build。

診斷指令：

# 直接去看 install 底下到底生出了什麼可執行檔
ls ~/ros2_ws/install/my_py_pkg/lib/my_py_pkg/
# 若是空的 → entry_points 沒生效
grep -A5 "console_scripts" ~/ros2_ws/src/my_py_pkg/setup.py

解法：修正 '指令名 = package名.檔名不含py:函式名'，然後一定要重 build。

③ 兩支節點都活著，但 listener 完全沒反應

真正原因（三選一）：(a) topic 名字不一致（大小寫、多底線、有沒有前導斜線）；(b) 訊息型別不一致（一邊 String 一邊 Int32）；(c) QoS 不相容（今天用預設不太會遇到，但 Day 2 講過的 sensor QoS 在 Day 8 接 /scan 時會爆）。

診斷 SOP（照這個順序，不要跳）：

ros2 topic list                  # 是不是有兩個長很像的 topic？
ros2 topic info /chatter -v      # Pub count / Sub count 是不是各為 1？
ros2 topic echo /chatter         # 外部收得到嗎？收得到 → 問題在 subscriber
ros2 node info /listener         # 它到底訂了什麼

助教話術：「ROS2 不會因為你名字打錯而報錯，它會很有禮貌地讓你等一輩子。所以沒反應比報錯更難查，一定要用 topic info -v 對數字。」

④ colcon build 出現 SetuptoolsDeprecationWarning 或 error in ... setup command

真正原因：Ubuntu 22.04 上 pip 升級過 setuptools（>=59 之後對 setup.py install 有棄用警告），與 ROS2 Humble 的 ament_python 相衝。只是 Warning 的話可以完全無視，但學生會被紅字嚇到。

診斷指令：

python3 -c "import setuptools; print(setuptools.__version__)"

解法：若真的 build 失敗（不是 warning），降版：pip3 install setuptools==58.2.0。提醒學生不要無腦 pip install --upgrade 任何東西，這是 ROS 環境爛掉的頭號原因。

⑤ 明明 build 成功，跑起來卻是舊版程式

真正原因：沒加 --symlink-install，install/ 裡是舊的複製品；或曾經在 src/ 裡誤 build 過，產生了第二組 install/ 造成環境混亂。

診斷指令：

ls -la ~/ros2_ws/install/my_py_pkg/lib/python3.10/site-packages/my_py_pkg/
# 若是 -> 指向 src 的箭頭，代表 symlink 生效；若是實體檔，就是複製品

find ~/ros2_ws/src -maxdepth 2 -name "install" -o -maxdepth 2 -name "build"
# 有東西 = 曾在 src 裡誤 build

核彈級解法（教學現場最常用）：

cd ~/ros2_ws
rm -rf build install log
colcon build --symlink-install
# 然後開新終端機重新 source

助教話術：「ROS2 的『重開機』就是 rm -rf build install log。這三個資料夾都是機器生的，刪掉不會弄丟任何你寫的東西——但 src/ 千萬別碰。」

  1. 完成了什麼（驗收清單勾了幾項）
  2. 卡在哪——請貼完整錯誤訊息，不要只寫「跑不動」
  3. 沒懂的概念（例如「overlay 到底是什麼還是不太懂」）
  4. 實際花的時間（我會據此調整 Day 4 的份量）
