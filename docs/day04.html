今天的主題其實只有一句話

Day 3 你會寫節點了。但一個真實機器人有 20–50 個節點，你不可能開 30 個終端機、每個都手打參數。

1. 知識點：自訂 msg

1-1　它解決什麼問題

ROS2 的節點是各自獨立的程式，可能一個是 C++、一個是 Python，可能跑在不同電腦上。它們之間要交換資料，就必須先講好「這串位元組怎麼解讀」。

內建的 std_msgs、geometry_msgs、sensor_msgs 已經涵蓋八成情境。但當你要傳「一次物件偵測的結果：類別 + 信心度 + 3D 位置」，就沒有現成的了。

助教要提醒學生的原則：先找有沒有現成的標準訊息，找不到再自訂。 例如偵測結果其實有 vision_msgs/Detection3DArray。自訂 msg 會讓你的套件跟別人的生態脫鉤——別人的工具（rviz plugin、rosbag 分析工具）不認得你的型別。

1-2　白話解釋 + 比喻

.msg 檔像報關單的欄位格式。建置時 rosidl（ROS Interface Definition Language）這套工具會讀它，然後幫你自動生成：C++ 的 struct 與標頭檔、Python 的 class、以及最重要的——序列化／反序列化程式碼（把記憶體裡的物件變成可以在網路上傳的位元組，以及反過來）。

所以請記牢這件事：你 import 的那個 Python class 不是任何人手寫的 .py，是建置時生成的。 這句話能解釋今天八成的錯誤。

1-3　msg 檔語法

# 基本型別
bool    flag
int8 int16 int32 int64          # 有號整數
uint8 uint16 uint32 uint64      # 無號整數
float32 float64
string  name

# 陣列
float64[]    unbounded_array     # 不限長度
float64[10]  fixed_array         # 固定 10 個
float64[<=10] bounded_array      # 最多 10 個

# 巢狀：直接用別的訊息型別
std_msgs/Header header
geometry_msgs/Point position

# 常數（全大寫 + 等號）
uint8 STATUS_IDLE=0
uint8 STATUS_MOVING=1
uint8 status

# 預設值（型別 名稱 預設值）
int32 count 0
string label "unknown"

1-4　為什麼介面一定要放在 ament_cmake package

因為 rosidl 的程式碼生成是 CMake 的功能，ament_python 的建置流程沒有這一段。

業界慣例，請學生照做：介面獨立成一個 package（例如 my_msgs），程式節點放另一個（my_nodes）。
原因：別人只想用你的訊息型別（例如寫一個訂閱者），不需要被迫安裝你所有的程式相依。而且介面 package 改動頻率低，可以獨立版本管理。

1-5　實作：建介面 package

source /opt/ros/humble/setup.bash
mkdir -p ~/day4_ws/src && cd ~/day4_ws/src

ros2 pkg create day4_msgs --build-type ament_cmake --dependencies std_msgs
mkdir -p day4_msgs/msg day4_msgs/srv

cat > day4_msgs/msg/Temperature.msg <<'EOF'
# 一次溫度量測
std_msgs/Header header      # frame_id = 感測器位置；stamp = 量測時刻
float32 celsius             # 攝氏溫度
float32 humidity            # 相對濕度 0~100 (%)
string  sensor_name         # 感測器代號
uint8 STATUS_OK=0
uint8 STATUS_OVERHEAT=1
uint8 status
EOF

cat > day4_msgs/srv/SetThreshold.srv <<'EOF'
# 請求：把警戒溫度設成多少
float32 threshold
---
# 回應：成功與否 + 訊息（--- 上面是 request，下面是 response）
bool success
string message
EOF

編輯 day4_msgs/CMakeLists.txt，在 ament_package() 之前加：

find_package(rosidl_default_generators REQUIRED)
find_package(std_msgs REQUIRED)

rosidl_generate_interfaces(${PROJECT_NAME}
  "msg/Temperature.msg"
  "srv/SetThreshold.srv"
  DEPENDENCIES std_msgs
)

編輯 day4_msgs/package.xml，加這三行：

  <buildtool_depend>rosidl_default_generators</buildtool_depend>
  <exec_depend>rosidl_default_runtime</exec_depend>
  <member_of_group>rosidl_interface_packages</member_of_group>

三行各是什麼意思（學生一定會問，你要答得出來）：

標籤意思
buildtool_depend建置時需要的工具：程式碼生成器本身
exec_depend執行時需要的函式庫：生成出來的程式碼要靠它才能跑
member_of_group向 ROS2 宣告「我是介面 package」，其他 package 才找得到我的型別
cd ~/day4_ws
colcon build --packages-select day4_msgs
source install/setup.bash

# 驗證（這兩行是你以後的標準診斷動作）
ros2 interface show day4_msgs/msg/Temperature
ros2 interface show day4_msgs/srv/SetThreshold
ros2 interface list | grep day4
常見誤解 1：「msg 存檔了程式就會用新欄位」。錯。改 msg 一定要重 colcon build，而且 --symlink-install 對它沒有用（symlink 只對純 Python 檔生效，生成的介面還是要重編）。
常見誤解 2：「我把 .msg 放在 Python package 裡就好」。ament_python 不會生成介面，build 會過但什麼都沒生出來，import 時才炸。

2. 知識點：Parameter 與 YAML

2-1　它解決什麼問題

「警戒溫度 40 度」這個數字，如果寫死在程式碼裡，每次要調就得改程式、重 build、重啟。參數讓這些數字變成外部設定。

比喻：程式碼是電器本體，參數是面板上的旋鈕。你不會為了調冷氣溫度而拆開機殼。

2-2　三個層次，一定要分清楚

層次做什麼不做會怎樣
declare_parameter(名稱, 預設值)向 ROS2 宣告「我有這個旋鈕」，同時決定型別沒宣告就 get 會拋 ParameterNotDeclaredException
get_parameter(名稱).value讀取當下的值—
add_on_set_parameters_callback()註冊「有人改我參數時要做什麼」執行期 ros2 param set 改了，你的程式不會知道
常見誤解：「我 ros2 param set 改了，程式怎麼沒反應？」
因為大部分教材的寫法是在 __init__ 讀一次就存進 self.xxx。改參數只改了 ROS 那邊的值，你的 self.xxx 沒變。要即時生效必須註冊 callback。這是學生最常見的「以為壞掉」情境，其實是設計如此。

2-3　YAML 的格式：那個 ros__parameters 是什麼

# 最外層 = 節點的「真實名稱」，不是檔名、不是 executable 名、不是 package 名
temp_sensor:
  ros__parameters:          # 固定寫法，兩條底線
    publish_rate: 2.0       # float：一定要寫小數點！寫 2 會變成 int，型別對不上
    sensor_name: "cpu_temp" # string
    threshold: 40.0
    enabled: true           # bool
    offsets: [0.1, -0.2]    # double array

# 有 namespace 的話要寫全名
/robot1/temp_sensor:
  ros__parameters:
    threshold: 35.0

# 萬用字元：所有節點都套用（常見於 use_sim_time）
/**:
  ros__parameters:
    use_sim_time: false
踩雷第一名：YAML 寫 publish_rate: 2（整數），程式裡 declare_parameter('publish_rate', 2.0)（浮點數）→ 直接拋 InvalidParameterTypeException。浮點參數在 YAML 一律寫成 2.0。

3. 知識點：Launch 檔

3-1　它解決什麼問題

一個 Nav2 系統要啟動十幾個節點，每個都有自己的參數與 remapping。Launch 檔就是啟動腳本 + 系統組裝說明書。

比喻：launch 檔是樂團的總譜——誰在什麼時候進場、用什麼調、接哪條線。

ROS2 的 launch 是 Python 程式（不像 ROS1 是 XML），所以你可以寫 if、for、讀環境變數。代價是語法比較繞。

3-2　最小可用的 launch 檔骨架

#!/usr/bin/env python3
import os
from ament_index_python.packages import get_package_share_directory
from launch import LaunchDescription
from launch.actions import DeclareLaunchArgument, IncludeLaunchDescription, LogInfo
from launch.substitutions import LaunchConfiguration
from launch_ros.actions import Node


def generate_launch_description():
    # 1) 宣告啟動參數：ros2 launch 時可以在指令列覆寫
    #    用法：ros2 launch day4_bringup demo.launch.py sim:=true
    sim_arg = DeclareLaunchArgument(
        'sim', default_value='false',
        description='是否使用模擬時間')
    sim = LaunchConfiguration('sim')

    # 2) 找到 package 的 share 目錄，組出 yaml 路徑
    params = os.path.join(
        get_package_share_directory('day4_bringup'),
        'config', 'demo_params.yaml')

    return LaunchDescription([
        sim_arg,
        LogInfo(msg=['啟動中，use_sim_time = ', sim]),

        Node(
            package='day4_bringup',
            executable='temp_sensor',       # setup.py entry_points 的名字
            name='temp_sensor',             # 節點的真實名稱，要與 YAML key 一致
            output='screen',                # log 印在終端機（不加就看不到 print）
            parameters=[params, {'use_sim_time': sim}],
            remappings=[('temperature', '/sensors/cpu_temp')],
        ),
        Node(
            package='day4_bringup',
            executable='temp_monitor',
            name='temp_monitor',
            output='screen',
            parameters=[params],
            remappings=[('temperature', '/sensors/cpu_temp')],
        ),
    ])

3-3　Node() 幾個一定要懂的引數

引數意義踩雷
name覆寫節點名稱改了它，YAML 的 key 也要跟著改
namespace在所有名稱前加前綴YAML key 要寫成 /ns/node:
output='screen'把 stdout 顯示出來不加的話 print() 與 log 都看不到，學生會以為程式沒跑
parameters=[...]list，可混用檔案路徑與 dict後面的會蓋掉前面的，順序有意義
remappings=[(舊,新)]換接線舊名要寫程式碼裡的原始名稱，不是你想像的名稱
arguments=[...]傳給程式的命令列參數與 ros-args 不同層次，別混淆

4. 知識點：Remapping 與 Namespace

4-1　Remapping：換接線

它解決什麼問題：你買了一個雷射雷達驅動套件，它固定發到 /scan。但你有兩顆雷達。你不會去改它的原始碼——你 remap。

比喻：remapping 是轉接頭，不是改電器。

# 指令列的寫法（--ros-args 之後才是 ROS 的參數）
ros2 run day4_bringup temp_sensor --ros-args \
  --remap temperature:=/sensors/cpu_temp \
  --remap __node:=my_sensor \
  -p threshold:=45.0

# 從檔案載入參數
ros2 run day4_bringup temp_sensor --ros-args --params-file /path/to/demo_params.yaml

4-2　Namespace：整組搬家

remapping 是一條一條換；namespace 是把這個節點的所有名稱整組加前綴。

Node(package='...', executable='temp_sensor',
     name='temp_sensor', namespace='robot1')
# → 節點變成 /robot1/temp_sensor
# → topic 從 temperature 變成 /robot1/temperature

典型用途：多機器人。同一套程式開兩次，一個 namespace 是 robot1、一個是 robot2，彼此不會打架。

4-3　名稱前面那個斜線，決定一切

相對名稱（temperature）→ 會被 namespace 加前綴 → 變成 /robot1/temperature
絕對名稱（/temperature）→ 不受 namespace 影響，永遠是 /temperature

寫程式時請一律用相對名稱，把要不要加前綴的決定權留給 launch 檔。學生若在程式裡寫死 /cmd_vel，之後做多機器人就得改原始碼——這正是 remapping 想避免的事。

5-2　day4_bringup/day4_bringup/temp_sensor.py

#!/usr/bin/env python3
"""假的溫度感測器：週期性發佈 Temperature，並提供一個改警戒值的 service。"""
import math
import random

import rclpy
from rclpy.node import Node
from rcl_interfaces.msg import SetParametersResult

from day4_msgs.msg import Temperature
from day4_msgs.srv import SetThreshold


class TempSensor(Node):
    def __init__(self):
        super().__init__('temp_sensor')

        # --- 宣告參數：第二個引數同時決定「預設值」與「型別」---
        self.declare_parameter('publish_rate', 2.0)
        self.declare_parameter('sensor_name', 'cpu_temp')
        self.declare_parameter('threshold', 40.0)
        self.declare_parameter('frame_id', 'cpu')

        rate = self.get_parameter('publish_rate').value
        self.sensor_name = self.get_parameter('sensor_name').value
        self.threshold = self.get_parameter('threshold').value
        self.frame_id = self.get_parameter('frame_id').value

        # --- 註冊參數變更 callback：讓 ros2 param set 能即時生效 ---
        self.add_on_set_parameters_callback(self.on_param_change)

        # 注意：這裡用「相對名稱」，把要不要加前綴留給 launch 決定
        self.pub = self.create_publisher(Temperature, 'temperature', 10)

        # Service：讓別人可以改警戒值
        self.srv = self.create_service(
            SetThreshold, 'set_threshold', self.on_set_threshold)

        self.t = 0.0
        self.dt = 1.0 / float(rate)
        self.create_timer(self.dt, self.tick)
        self.get_logger().info(
            f'temp_sensor 啟動：{rate} Hz, threshold={self.threshold}')

    def on_param_change(self, params):
        """有人 ros2 param set 時會呼叫這裡。回傳 successful=False 就是拒絕。"""
        for p in params:
            if p.name == 'threshold':
                if p.value < 0.0:
                    return SetParametersResult(
                        successful=False, reason='threshold 不可為負')
                self.threshold = p.value
                self.get_logger().info(f'threshold 已更新為 {self.threshold}')
        return SetParametersResult(successful=True)

    def on_set_threshold(self, req, res):
        if req.threshold < 0.0:
            res.success = False
            res.message = 'threshold 不可為負'
        else:
            self.threshold = float(req.threshold)
            res.success = True
            res.message = f'threshold 設為 {self.threshold}'
        self.get_logger().info(res.message)
        return res

    def tick(self):
        self.t += self.dt
        celsius = 38.0 + 6.0 * math.sin(0.2 * self.t) + random.gauss(0.0, 0.3)

        msg = Temperature()
        msg.header.stamp = self.get_clock().now().to_msg()
        msg.header.frame_id = self.frame_id
        msg.celsius = float(celsius)
        msg.humidity = 55.0
        msg.sensor_name = self.sensor_name
        msg.status = (Temperature.STATUS_OVERHEAT
                      if celsius > self.threshold else Temperature.STATUS_OK)
        self.pub.publish(msg)


def main():
    rclpy.init()
    node = TempSensor()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    finally:
        node.destroy_node()
        rclpy.try_shutdown()


if __name__ == '__main__':
    main()

5-3　day4_bringup/day4_bringup/temp_monitor.py

#!/usr/bin/env python3
"""訂閱 Temperature，超過警戒值就警告。示範用常數欄位判斷狀態。"""
import rclpy
from rclpy.node import Node

from day4_msgs.msg import Temperature


class TempMonitor(Node):
    def __init__(self):
        super().__init__('temp_monitor')
        self.declare_parameter('log_every_n', 5)
        self.n = int(self.get_parameter('log_every_n').value)
        self.count = 0

        self.sub = self.create_subscription(
            Temperature, 'temperature', self.on_temp, 10)
        self.get_logger().info('temp_monitor 啟動，等待資料…')

    def on_temp(self, msg: Temperature):
        self.count += 1
        if msg.status == Temperature.STATUS_OVERHEAT:
            self.get_logger().warn(
                f'[{msg.sensor_name}] 過熱：{msg.celsius:.1f} °C',
                throttle_duration_sec=2.0)
        elif self.count % self.n == 0:
            self.get_logger().info(
                f'[{msg.sensor_name}] {msg.celsius:.1f} °C '
                f'@ frame={msg.header.frame_id}')


def main():
    rclpy.init()
    node = TempMonitor()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    finally:
        node.destroy_node()
        rclpy.try_shutdown()


if __name__ == '__main__':
    main()

9. 🎓 助教筆記：Day 4 學生最會卡的地方

卡點 1：ModuleNotFoundError: No module named 'day4_msgs'

依序檢查：
① 有沒有 colcon build？② build 完有沒有重新 source？③ 是不是在舊終端機執行？④ day4_bringup/package.xml 裡有沒有 <depend>day4_msgs</depend>？

診斷：ros2 interface list | grep day4（有列出 = 介面裝好了，是環境問題；沒列出 = build 沒成功）

絕招：rm -rf build install log && colcon build，然後開全新終端機。

卡點 2：介面 package build 過了，但別的 package 找不到型別

錯誤訊息：CMake Error: Could not find a package configuration file provided by "day4_msgs"，或 Python 端 import 成功但欄位不對。

原因：package.xml 少了 <member_of_group>rosidl_interface_packages</member_of_group>，或 rosidl_generate_interfaces 寫在 ament_package() 後面（CMake 是照順序執行的，寫在後面等於沒寫）。

診斷：ls ~/day4_ws/install/day4_msgs/lib/python3.10/site-packages/day4_msgs/msg/ —— 有 _temperature.py 之類的檔案，代表真的生成了。

卡點 3：YAML 參數沒吃到（不報錯，最陰險）

症狀：程式跑得好好的，但行為是預設值。

診斷三連：
ros2 node list → 節點的真實名稱是什麼
ros2 param dump /節點名 → 實際生效的參數
cat 你的.yaml → 比對最外層 key

四個常見原因：
① YAML key 寫成 package 名或檔名，不是節點名
② launch 裡設了 namespace，key 卻沒寫成 /ns/node:
③ 縮排錯誤（YAML 對縮排極敏感，不能用 Tab，只能空格）
④ 改了 YAML 但沒重 colcon build——YAML 是被複製到 install/ 的，改原始檔沒用（除非用 --symlink-install）

助教話術：「先 ros2 param dump 給我看，我們比對一下你以為的和實際的。」

卡點 4：launch file was not found in the share directory

原因：setup.py 的 data_files 沒裝 launch 目錄；或 glob pattern 對不上（檔名沒有 .launch.py 結尾，而 glob 寫的是 launch/*.launch.py）。

診斷：ls ~/day4_ws/install/day4_bringup/share/day4_bringup/ —— 直接看裝進去了沒。

順便教學生：這個 install/.../share/ 就是 get_package_share_directory() 回傳的路徑。理解這件事，之後找任何套件的預設參數檔都靠它。

卡點 5：remap 沒有生效

原因排序：
① 程式裡寫的是絕對名稱（/temperature），remap 的舊名寫成相對名稱 → 對不上
② remap 的「舊名」寫成了自己想要的名稱，方向搞反了（正確是 (原始名, 新名)）
③ 用 ros2 run 時忘了 --ros-args

診斷：ros2 node info /節點名 直接看它實際訂閱／發佈的完整 topic 名稱，一翻兩瞪眼。

卡點 6：launch 起來了但什麼 log 都沒有，像當機

原因：Node() 少了 output='screen'。ROS2 預設把 log 導到 ~/.ros/log/，不顯示在終端機。

解法：加 output='screen'；或整份 launch 執行時加 --ros-args --log-level debug；或直接去翻 ~/.ros/log/latest_launch/。

這一條要教學生養成習慣：看不到輸出 ≠ 沒在跑。先 ros2 node list 確認節點活著，再處理 log。
