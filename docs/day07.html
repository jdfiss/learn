2. 知識點逐個講解

2-1　為什麼要自訂 msg？它到底做了什麼

它解決什麼問題：ROS2 的節點是獨立的程式，可能一個 C++ 一個 Python，可能在不同電腦上。它們之間要交換資料，就必須先講好「這串位元組怎麼解讀」。自訂 msg 就是這份契約。

白話 + 比喻：msg 檔像是報關單的欄位格式。你寫好 float32 distance，建置時 rosidl 會幫你在 C++ / Python 各生一個對應的類別、外加序列化程式碼。所以自訂 msg 一定要 build 過、而且要 source 過，Python 才 import 得到——它不是你手寫的 .py 檔，是建置時生成的。

常見誤解：「我 msg 檔改好存檔了，程式應該就會用新的欄位」。錯。msg 改了必須重 colcon build，而且 --symlink-install 對它沒有幫助（symlink 只對純 Python 檔有效，生成的介面還是要重編）。學生最常在這裡卡半小時。

2-2　移動平均濾波：最簡單、但天天用得到

它解決什麼問題：真實感測器讀值會抖。抖動會讓「距離小於 0.8 公尺就停車」這種判斷瘋狂跳動（一下停一下走）。

公式：
y[k] = (1/N) · ( x[k] + x[k-1] + … + x[k-N+1] )

  • x[k]：第 k 次的原始感測器讀值（例如這一幀量到的距離，單位公尺）
  • y[k]：第 k 次的濾波後輸出，你真正拿去做決策的值
  • N：視窗大小，代表「我要拿最近幾筆來平均」

參數調哪會怎樣（這就是你要能回答學生的層次）：N 調大 → 輸出更平滑，但延遲更大，大約延遲 (N-1)/2 個週期。10 Hz 感測器用 N=21，等於延遲一秒才反應到障礙物——機器人已經撞上去了。這個「平滑 vs 反應速度」的取捨，之後在 Nav2 調參（Day 11）、控制器（Day 13）會一再出現，是同一個道理。

常見誤解：「濾波器可以把雜訊完全去掉」。不行。濾波是用時間換平滑，你永遠在付延遲的代價。沒有免費的午餐。

2-3　極座標 → 直角座標：感測器資料的第一步永遠是這個

雷射、雷達、超音波量到的是「距離 + 角度」（極座標），但 tf2、rviz、路徑規劃全部吃「x, y, z」（直角座標）。

x = d · cos(θ)　y = d · sin(θ)　z = 0

  • d：距離，公尺，從感測器原點算起
  • θ：角度，弧度，ROS 慣例是繞 z 軸從 +x 軸逆時針為正
  • 算出來的 (x, y) 是在感測器自己的座標系裡——這件事極重要，見下一節
常見誤解：學生把角度用「度」代進 math.cos()。Python 的三角函數吃弧度，代 90 進去它算的是 90 弧度。結果是點跑到奇怪的地方但程式不會報錯——這種「不報錯的錯」最難抓。

2-4　frame_id 與 header.stamp：兩個決定成敗的欄位

它解決什麼問題：你算出 (x, y) = (1.2, 0.4)，這是「相對誰」的 1.2 公尺？沒有 frame_id，這組數字毫無意義。

比喻：frame_id 是「從哪棟樓的大門開始算」，header.stamp 是「什麼時候量的」。tf2 的工作就是：給我一個時間點與兩個 frame，我告訴你換算矩陣。所以這兩個欄位任一個亂填，tf2 就會拒絕服務。

三個必背習慣：
① 任何有 header 的訊息，frame_id 一定要填，而且要填資料真正產生的那個 frame（雷射資料就填 laser_link，不要偷懶填 base_link）。
② stamp 要填量測的時刻，不是發佈的時刻（今天先用發佈時刻沒關係，Day 18 做多感測器同步時會回來咬你）。
③ 想在 rviz 看到東西，rviz 左上角的 Fixed Frame 必須能透過 tf 連到你資料的 frame_id。

2-5　visualization_msgs/Marker：你的第一個除錯工具

它解決什麼問題：機器人程式最痛苦的地方是「數字對不對看不出來」。Marker 讓你把中間結果畫在 3D 空間裡，一眼就知道座標轉換有沒有搞反。

比喻：Marker 就是機器人版的 print()。以後你會發現，一半的除錯時間是靠「把它畫出來」解決的。

幾個一定要記住的欄位：

欄位意義踩雷點
ns + idMarker 的身分證id 一直遞增 → 舊的不會消失，畫面愈來愈卡
actionADD(0) / DELETE(2) / DELETEALL(3)要清畫面用 DELETEALL
scale大小，單位公尺忘了設 → 全是 0 → 什麼都看不到
color.a不透明度預設 0 = 完全透明，最常見的「沒畫出來」原因
lifetime存活時間，0 = 永久設太短會閃爍

檔案路徑：~/week1_ws/src/week1_bringup/week1_bringup/fake_sensor.py

#!/usr/bin/env python3
"""假的距離感測器：週期性發佈一個會來回移動、帶雜訊的障礙物偵測結果。"""
import math
import random

import rclpy
from rclpy.node import Node
from week1_msgs.msg import Detection


class FakeSensor(Node):
    def __init__(self):
        super().__init__('fake_sensor')

        # --- Day 4：參數宣告，第二個引數是預設值 ---
        self.declare_parameter('publish_rate', 10.0)   # Hz
        self.declare_parameter('noise_std', 0.03)      # 公尺，高斯雜訊標準差
        self.declare_parameter('frame_id', 'laser_link')

        rate = self.get_parameter('publish_rate').value
        self.noise_std = self.get_parameter('noise_std').value
        self.frame_id = self.get_parameter('frame_id').value

        # --- Day 3：建立 publisher，queue depth 10 ---
        self.pub = self.create_publisher(Detection, 'detection', 10)

        self.dt = 1.0 / float(rate)
        self.t = 0.0
        self.create_timer(self.dt, self.tick)
        self.get_logger().info(
            f'fake_sensor 啟動：{rate} Hz, frame_id={self.frame_id}')

    def tick(self):
        self.t += self.dt

        # 真值：距離在 0.7~2.3 公尺之間來回，角度左右擺動
        true_d = 1.5 + 0.8 * math.sin(0.5 * self.t)
        true_a = 0.6 * math.sin(0.3 * self.t)

        msg = Detection()
        msg.header.stamp = self.get_clock().now().to_msg()   # 一定要填
        msg.header.frame_id = self.frame_id                  # 一定要填
        msg.distance = float(max(true_d + random.gauss(0.0, self.noise_std), 0.05))
        msg.angle = float(true_a)
        msg.label = 'box'
        self.pub.publish(msg)


def main():
    rclpy.init()
    node = FakeSensor()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    finally:
        node.destroy_node()
        rclpy.try_shutdown()


if __name__ == '__main__':
    main()

3-4　節點二：detector.py（濾波 + 座標轉換 + Marker）

檔案路徑：~/week1_ws/src/week1_bringup/week1_bringup/detector.py

#!/usr/bin/env python3
"""訂閱 Detection → 移動平均濾波 → 極座標轉直角 → 發佈 PointStamped 與 Marker。"""
import math
from collections import deque

import rclpy
from rclpy.node import Node
from geometry_msgs.msg import PointStamped
from visualization_msgs.msg import Marker
from week1_msgs.msg import Detection


class Detector(Node):
    def __init__(self):
        super().__init__('detector')

        self.declare_parameter('window_size', 5)      # 移動平均視窗 N
        self.declare_parameter('warn_distance', 0.9)  # 公尺，小於就變紅色警告

        n = int(self.get_parameter('window_size').value)
        self.warn_distance = float(self.get_parameter('warn_distance').value)

        self.buf = deque(maxlen=max(n, 1))            # 只留最近 N 筆

        self.sub = self.create_subscription(
            Detection, 'detection', self.on_detection, 10)
        self.pub_point = self.create_publisher(PointStamped, 'obstacle_point', 10)
        self.pub_marker = self.create_publisher(Marker, 'obstacle_marker', 10)

        self.get_logger().info(
            f'detector 啟動：window_size={n}, warn_distance={self.warn_distance} m')

    def on_detection(self, msg: Detection):
        # --- 1) 移動平均濾波（只濾距離；角度也可以照做）---
        self.buf.append(msg.distance)
        d = sum(self.buf) / len(self.buf)

        # --- 2) 極座標 → 直角座標（注意：angle 是弧度）---
        x = d * math.cos(msg.angle)
        y = d * math.sin(msg.angle)

        # --- 3) 發佈點：header 原封不動沿用，frame 與時間才不會錯 ---
        pt = PointStamped()
        pt.header = msg.header
        pt.point.x = float(x)
        pt.point.y = float(y)
        pt.point.z = 0.0
        self.pub_point.publish(pt)

        # --- 4) 發佈 Marker 給 rviz2 畫 ---
        too_close = d < self.warn_distance

        m = Marker()
        m.header = msg.header          # frame_id 跟資料一致，交給 tf2 換算
        m.ns = 'obstacle'
        m.id = 0                       # 固定 id：新的蓋掉舊的，不會愈畫愈多
        m.type = Marker.SPHERE
        m.action = Marker.ADD
        m.pose.position.x = float(x)
        m.pose.position.y = float(y)
        m.pose.position.z = 0.0
        m.pose.orientation.w = 1.0     # 單位四元數＝不旋轉，忘了填會是全 0 的非法值
        m.scale.x = m.scale.y = m.scale.z = 0.25   # 直徑 25 公分
        m.color.r = 1.0 if too_close else 0.1
        m.color.g = 0.2 if too_close else 0.8
        m.color.b = 0.2
        m.color.a = 0.9                # 千萬別忘，預設 0 = 隱形
        self.pub_marker.publish(m)

        if too_close:
            # throttle：同樣訊息 2 秒內只印一次，避免洗版
            self.get_logger().warn(
                f'障礙物過近：{d:.2f} m', throttle_duration_sec=2.0)


def main():
    rclpy.init()
    node = Detector()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    finally:
        node.destroy_node()
        rclpy.try_shutdown()


if __name__ == '__main__':
    main()

檔案路徑：~/week1_ws/src/week1_bringup/week1_bringup/odom_faker.py

#!/usr/bin/env python3
"""假的里程計：讓 base_link 在 odom 座標系裡繞圈，用來驗證 tf2 換算是否正確。"""
import math

import rclpy
from rclpy.node import Node
from geometry_msgs.msg import TransformStamped
from tf2_ros import TransformBroadcaster


class OdomFaker(Node):
    def __init__(self):
        super().__init__('odom_faker')
        self.br = TransformBroadcaster(self)
        self.t = 0.0
        self.dt = 0.05                       # 20 Hz
        self.create_timer(self.dt, self.tick)

    def tick(self):
        self.t += self.dt
        # 半徑 1 公尺的圓，角速度 0.4 rad/s
        r, w = 1.0, 0.4
        yaw = w * self.t

        tf = TransformStamped()
        tf.header.stamp = self.get_clock().now().to_msg()
        tf.header.frame_id = 'odom'          # parent
        tf.child_frame_id = 'base_link'      # child
        tf.transform.translation.x = r * math.cos(yaw)
        tf.transform.translation.y = r * math.sin(yaw)
        tf.transform.translation.z = 0.0

        # 繞 z 軸旋轉 yaw 的四元數：只有 z, w 非零
        tf.transform.rotation.z = math.sin(yaw / 2.0)
        tf.transform.rotation.w = math.cos(yaw / 2.0)

        self.br.sendTransform(tf)


def main():
    rclpy.init()
    node = OdomFaker()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    finally:
        node.destroy_node()
        rclpy.try_shutdown()


if __name__ == '__main__':
    main()

import os
from ament_index_python.packages import get_package_share_directory
from launch import LaunchDescription
from launch_ros.actions import Node


def generate_launch_description():
    params = os.path.join(
        get_package_share_directory('week1_bringup'),
        'config', 'week1_params.yaml')

    return LaunchDescription([
        # 靜態 tf：base_link → laser_link
        # 參數順序 x y z yaw pitch roll parent child（Humble 建議用 --frame-id 寫法）
        Node(
            package='tf2_ros',
            executable='static_transform_publisher',
            name='base_to_laser',
            arguments=[

6. 🎓 助教筆記：第一週學生最會卡的地方

下面每一條都請你親手製造一次（把對應的東西弄壞、看到錯誤訊息、再修好）。看過和修過是兩回事。

卡點 1：改了 msg 但程式還是用舊的欄位

錯誤訊息：AttributeError: 'Detection' object has no attribute 'label'，或 ModuleNotFoundError: No module named 'week1_msgs'

診斷：
ros2 interface show week1_msgs/msg/Detection（看安裝的版本是不是舊的）
echo $AMENT_PREFIX_PATH（看有沒有 source 到 workspace）

解法：colcon build --packages-select week1_msgs 後開新終端機重新 source install/setup.bash。仍不行就 rm -rf build install log 全部重來。

為什麼：介面是建置期生成的；--symlink-install 只對純 Python 檔有效，對生成的介面無效。而且 shell 環境變數是 source 當下的快照，舊終端機看不到新裝的東西。

卡點 2：rviz2 什麼都沒有

症狀：topic 明明有資料（ros2 topic hz 正常），rviz 一片空白，或 Marker 顯示項旁邊亮黃/紅字。

診斷順序（固定這樣問學生，五個問題內一定找到）：

  1. Fixed Frame 設對了嗎？（設成 odom，不要留預設的 map——沒有人發佈 map 就永遠是紅字）
  2. Marker 的 color.a 是不是 0？
  3. scale 是不是 0？
  4. header.frame_id 是不是空字串？ros2 topic echo /obstacle_marker --once 直接看
  5. pose.orientation 是不是全 0？（合法四元數的模長必須是 1，全 0 會被 rviz 拒絕並警告 Uninitialized quaternion, assuming identity）

錯誤訊息範例：[rviz2]: Message Filter dropping message: frame 'laser_link' at time ... for reason 'discarding message because the queue is full' → 這其實是 tf 問題不是 rviz 問題，往卡點 3 走。

卡點 3：tf 相關錯誤（整個第一週最常見）

錯誤訊息 A：Could not find a connection between 'odom' and 'laser_link' because they are not part of the same tree
→ 少發佈了中間某一段。ros2 run tf2_tools view_frames 產生 frames.pdf，一看就知道斷在哪。

錯誤訊息 B：Lookup would require extrapolation into the future. Requested time 1754... but the latest data is at time 1754...
→ 你查詢的時間比 tf 現有資料還新。臨時解法是查詢時用 rclpy.time.Time()（代表「最新可用」）而不是 msg.header.stamp；正解是拉高 broadcaster 頻率或加 Buffer(cache_time)。

錯誤訊息 C：TF_OLD_DATA ignoring data from the past / 時間戳跳來跳去
→ 九成是 use_sim_time 沒統一。有跑 Gazebo 時所有節點都要 use_sim_time:=true，Day 8 會正式踩這個坑。

錯誤訊息 D：TF_REPEATED_DATA ignoring data with redundant timestamp
→ 同一個 parent→child 有兩個東西在發（例如你自己發了一個、launch 裡的 static publisher 也發了一個）。一個 child frame 只能有一個 parent、只能有一個發佈者，這是 tf 的鐵律。

卡點 4：launch 找不到檔案 / 參數沒吃到

錯誤訊息：file 'week1.launch.py' was not found in the share directory
→ setup.py 的 data_files 忘了裝 launch 目錄。改完要重 build。

症狀：不報錯，但 ros2 param get /detector window_size 拿到的還是預設值。
診斷：ros2 node list 看節點的真實名稱，再比對 YAML 最外層的 key。
原因：YAML 的 key 必須是節點名稱。若 launch 裡寫了 namespace='robot1'，key 就要寫成 /robot1/detector:。學生最常把 key 寫成 package 名或檔名。
萬用招：ros2 param dump /detector 印出節點實際生效的所有參數，跟 YAML 對照。

卡點 5：ros2 run 說找不到 executable

錯誤訊息：No executable found

三個原因照順序檢查：① setup.py 的 entry_points 漏了；② build 完沒重新 source；③ 檔案放錯層（要在 week1_bringup/week1_bringup/ 底下，不是 week1_bringup/ 底下）。

診斷：ros2 pkg executables week1_bringup 直接列出這個 package 有哪些可執行檔。

卡點 6：兩台電腦互看得到 / 看不到對方的 topic

症狀：教室裡學生 A 的 ros2 topic list 冒出別人的 topic；或自己的節點彼此看不到。

診斷：echo $ROS_DOMAIN_ID（沒設就是 0，全班同一個網域，一定互相干擾）

解法：每位學生在 ~/.bashrc 加 export ROS_DOMAIN_ID=<自己的座號>（取 0–101 之間）。這件事要在課程第一天就統一規定，否則第一週會被這個問題吃掉大量時間。另外 export ROS_LOCALHOST_ONLY=1 可以直接把自己關在本機，是最省事的隔離方式。
