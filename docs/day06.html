今日目標：今天結束時，你要能從零寫出一台差速輪機器人的 URDF（用 Xacro），在 rviz2 裡看到它、拖動輪子看它轉、並且理解昨天手寫的那些 static transform 為什麼今天可以全部刪掉——因為 URDF 會自動幫你發。

1. 昨天的伏筆：URDF 就是「自動化的 tf 發佈器」

昨天你手打了這行：

ros2 run tf2_ros static_transform_publisher --x 0.2 --z 0.15 \
  --frame-id base_link --child-frame-id laser_link

一台真實機器人有 15–30 個 frame。你不可能打 30 行。

URDF 解決的就是這件事：用一份 XML 描述「機器人有哪些零件、彼此怎麼接、接在哪」，然後 robot_state_publisher 讀了它，自動把整棵 tf 樹發出來。

比喻：URDF 是機器人的樂高說明書——每一塊積木長什麼樣、多重、接在哪一塊的哪個位置、能不能轉。robot_state_publisher 是照著說明書把積木組起來並持續回報每塊積木現在在哪的那個人。

3. 知識點：URDF 的基本結構

3-1　只有兩種元素：link 與 joint

link（連桿）＝ 一塊剛體零件。車體、輪子、手臂的一節、雷達本體。
joint（關節）＝ 兩個 link 之間的連接關係，同時也定義了它們的相對位置。

結構永遠是：link — joint — link — joint — link … 交錯成一棵樹。
每個 link 只能有一個 parent joint——這就是昨天 tf 那條鐵律的來源。

3-2　joint 的六種類型

type意義典型用途需要 joint_state 嗎
fixed焊死，不會動雷達、相機、IMU 的安裝不用
continuous繞軸無限旋轉輪子要
revolute繞軸旋轉有上下限手臂關節要
prismatic沿軸直線滑動，有限位夾爪、升降柱要
floating6 自由度自由浮動幾乎不用—
planar平面內 3 自由度幾乎不用—

Day 15 開始碰 MoveIt2 時，你會發現手臂就是一串 revolute joint——今天學的東西直接延續過去。

3-3　最重要的坑：兩個 origin 完全不同

這是 URDF 的頭號困惑點，助教一定要講清楚。

① joint 裡的 origin　→ 決定子 link 的座標系原點要放在父 link 的哪裡。它會影響 tf。
② visual / collision / inertial 裡的 origin　→ 決定那塊幾何形狀相對於「自己這個 link 的原點」要偏移多少。它不影響 tf，只影響外觀。

比喻：joint 的 origin 是「這塊積木釘在母積木的哪個位置」；visual 的 origin 是「這塊積木的圖案要印在積木本身的哪個位置」。

實務判斷：模型整台歪掉、輪子飛到旁邊 → 通常是 joint 的 origin 錯。模型位置對但形狀陷進地板一半 → 通常是 visual 的 origin 沒補。

常見誤解：「圓柱體預設是躺著的」。不是，URDF 的 cylinder 預設沿 z 軸站立。輪子要立起來（軸朝 y），必須在 joint 或 visual 的 rpy 加上繞 x 軸 −90 度（-1.5708）。學生 90% 第一次做出來的輪子是躺平的。

3-4　visual / collision / inertial：三個都要有，用途各不同

區塊誰會用該寫什麼
visualrviz2、Gazebo 畫面好看的形狀，可以用 mesh（.dae/.stl）
collision物理引擎、MoveIt2 碰撞檢查盡量用簡單幾何（box/cylinder/sphere）。用複雜 mesh 會讓模擬慢十倍
inertial物理引擎（Gazebo / Isaac）質量與慣量張量。只在模擬會動的物體上重要
Day 8 的預告：inertial 寫錯（質量 0、慣量全 0、或慣量遠小於合理值）在 rviz2 完全看不出來，但一放進 Gazebo 就會出現「機器人瘋狂抖動、原地爆炸、穿過地板」。這是學生進入模擬後第一個崩潰點，今天就把慣量算對。

3-5　慣量怎麼算（不用背，但要知道在算什麼）

慣量張量描述「這個物體繞各個軸轉起來有多費力」，就像質量描述「推它前進有多費力」。

實心長方體（長 x、寬 y、高 z，質量 m）： ixx = m·(y² + z²)/12 iyy = m·(x² + z²)/12 izz = m·(x² + y²)/12 實心圓柱（半徑 r、高 h、質量 m，軸沿 z）： ixx = iyy = m·(3r² + h²)/12 izz = m·r²/2
  • m：質量，公斤
  • ixx：繞 x 軸轉動的慣量，單位 kg·m²
  • 非對角項 ixy, ixz, iyz：形狀不對稱時才非零，我們用規則幾何體，一律填 0
  • 物理直覺：質量離轉軸越遠，慣量越大（所以公式裡是平方）。花式滑冰選手收手轉更快，就是慣量變小

下面的 Xacro 會把這兩條公式寫成巨集，以後直接呼叫就好。

3-6　robot_state_publisher vs joint_state_publisher

這兩個名字很像，但做的事完全不同，學生一定會搞混。

joint_state_publisher：回答「每個可動關節現在轉到幾度？」
→ 發佈 /joint_states（sensor_msgs/JointState）
→ 真實機器人上，這是馬達驅動器回報的；開發階段用 joint_state_publisher_gui 拉滑桿假裝。

robot_state_publisher：拿 URDF（形狀結構）＋ /joint_states（關節角度），算出整棵 tf 樹並發佈。
→ 固定的 joint 發到 /tf_static，可動的發到 /tf。

一句話：joint_state_publisher 提供「角度」，robot_state_publisher 負責「換算成座標」。

常見誤解：「我只跑 robot_state_publisher 就好」。如果 URDF 裡有 continuous / revolute joint，沒有 /joint_states，那幾段 tf 永遠不會被發佈，rviz 就會說輪子找不到 transform。這是今天最常見的錯誤。

4. 知識點：Xacro

它解決什麼問題：純 URDF 極度囉唆。四個輪子要寫四遍幾乎一樣的 40 行。改一個尺寸要改十個地方。

Xacro（XML Macros）是一個預處理器——它在 URDF 之上加了「變數、數學運算、巨集、include」，最後展開成純 URDF。ROS 其實只認得純 URDF。

三個功能就夠用：

<!-- ① 屬性（變數）-->
<xacro:property name="wheel_radius" value="0.05"/>

<!-- ② 用 ${} 取值，裡面可以做數學運算 -->
<origin xyz="0 0 ${wheel_radius + base_height/2}"/>

<!-- ③ 巨集：把重複的東西包起來 -->
<xacro:macro name="wheel" params="prefix reflect">
   ...內容裡可以用 ${prefix} 與 ${reflect}...
</xacro:macro>
<xacro:wheel prefix="left"  reflect="1"/>
<xacro:wheel prefix="right" reflect="-1"/>

<!-- ④ 拆檔案 -->
<xacro:include filename="$(find my_robot_description)/urdf/wheel.xacro"/>
最重要的除錯指令：
xacro robot.urdf.xacro —— 把展開後的純 URDF 印出來。
學生說「我的 URDF 有問題」時，第一件事永遠是叫他先跑這個。八成的錯誤（語法、變數沒定義、巨集參數少給）在這一步就會直接報行號。

5-2　urdf/inertial_macros.xacro（慣量巨集，一次寫好永遠重用）

<?xml version="1.0"?>
<robot xmlns:xacro="http://www.ros.org/wiki/xacro">

  <!-- 實心長方體的慣量 -->
  <xacro:macro name="inertial_box" params="mass x y z *origin">
    <inertial>
      <xacro:insert_block name="origin"/>
      <mass value="${mass}"/>
      <inertia ixx="${(mass/12) * (y*y + z*z)}" ixy="0.0" ixz="0.0"
               iyy="${(mass/12) * (x*x + z*z)}" iyz="0.0"
               izz="${(mass/12) * (x*x + y*y)}"/>
    </inertial>
  </xacro:macro>

  <!-- 實心圓柱的慣量（軸沿 z）-->
  <xacro:macro name="inertial_cylinder" params="mass length radius *origin">
    <inertial>
      <xacro:insert_block name="origin"/>
      <mass value="${mass}"/>
      <inertia ixx="${(mass/12) * (3*radius*radius + length*length)}" ixy="0.0" ixz="0.0"
               iyy="${(mass/12) * (3*radius*radius + length*length)}" iyz="0.0"
               izz="${(mass/2) * (radius*radius)}"/>
    </inertial>
  </xacro:macro>

  <!-- 實心球的慣量 -->
  <xacro:macro name="inertial_sphere" params="mass radius *origin">
    <inertial>
      <xacro:insert_block name="origin"/>
      <mass value="${mass}"/>
      <inertia ixx="${(2/5) * mass * radius * radius}" ixy="0.0" ixz="0.0"
               iyy="${(2/5) * mass * radius * radius}" iyz="0.0"
               izz="${(2/5) * mass * radius * radius}"/>
    </inertial>
  </xacro:macro>

</robot>

*origin 前面那個星號代表「這是一個區塊參數」——呼叫時可以塞一整段 XML 進去，用 xacro:insert_block 展開。這是 Xacro 比較進階但很實用的語法。

5-3　urdf/my_robot.urdf.xacro（主檔）

<?xml version="1.0"?>
<robot xmlns:xacro="http://www.ros.org/wiki/xacro" name="my_robot">

  <xacro:include filename="$(find my_robot_description)/urdf/inertial_macros.xacro"/>

  <!-- ===== 尺寸參數：改這裡就好，全車跟著變 ===== -->
  <xacro:property name="base_length" value="0.35"/>
  <xacro:property name="base_width"  value="0.25"/>
  <xacro:property name="base_height" value="0.10"/>
  <xacro:property name="wheel_radius" value="0.055"/>
  <xacro:property name="wheel_width"  value="0.03"/>
  <xacro:property name="caster_radius" value="0.02"/>
  <xacro:property name="PI" value="3.14159265359"/>

  <!-- ===== 顏色 ===== -->
  <material name="blue"><color rgba="0.2 0.4 0.8 1.0"/></material>
  <material name="dark"><color rgba="0.15 0.15 0.15 1.0"/></material>
  <material name="red"><color rgba="0.8 0.2 0.2 1.0"/></material>

  <!-- ===== base_footprint：地面上的投影點，Nav2 慣例的根 ===== -->
  <link name="base_footprint"/>

  <joint name="base_joint" type="fixed">
    <parent link="base_footprint"/>
    <child  link="base_link"/>
    <!-- 車體中心離地：輪半徑 + 車體高度的一半 -->
    <origin xyz="0 0 ${wheel_radius + base_height/2}" rpy="0 0 0"/>
  </joint>

  <!-- ===== 車體 ===== -->
  <link name="base_link">
    <visual>
      <origin xyz="0 0 0" rpy="0 0 0"/>
      <geometry><box size="${base_length} ${base_width} ${base_height}"/></geometry>
      <material name="blue"/>
    </visual>
    <collision>
      <origin xyz="0 0 0" rpy="0 0 0"/>
      <geometry><box size="${base_length} ${base_width} ${base_height}"/></geometry>
    </collision>
    <xacro:inertial_box mass="3.0" x="${base_length}" y="${base_width}" z="${base_height}">
      <origin xyz="0 0 0" rpy="0 0 0"/>
    </xacro:inertial_box>
  </link>

  <!-- ===== 輪子巨集：左右各呼叫一次 ===== -->
  <xacro:macro name="wheel" params="prefix reflect">
    <link name="${prefix}_wheel_link">
      <visual>
        <origin xyz="0 0 0" rpy="0 0 0"/>
        <geometry><cylinder radius="${wheel_radius}" length="${wheel_width}"/></geometry>
        <material name="dark"/>
      </visual>
      <collision>
        <origin xyz="0 0 0" rpy="0 0 0"/>
        <geometry><cylinder radius="${wheel_radius}" length="${wheel_width}"/></geometry>
      </collision>
      <xacro:inertial_cylinder mass="0.3" length="${wheel_width}" radius="${wheel_radius}">
        <origin xyz="0 0 0" rpy="0 0 0"/>
      </xacro:inertial_cylinder>
    </link>

    <joint name="${prefix}_wheel_joint" type="continuous">
      <parent link="base_link"/>
      <child  link="${prefix}_wheel_link"/>
      <!-- rpy 的 -PI/2 是關鍵：把預設站立的圓柱「放倒」成輪子 -->
      <origin xyz="0 ${reflect * (base_width/2 + wheel_width/2)} ${-base_height/2}"
              rpy="${-PI/2} 0 0"/>
      <!-- axis 是「在子 link 自己的座標系裡」的旋轉軸 -->
      <axis xyz="0 0 1"/>
    </joint>
  </xacro:macro>

  <xacro:wheel prefix="left"  reflect="1"/>
  <xacro:wheel prefix="right" reflect="-1"/>

  <!-- ===== 前方萬向輪（用球體代替）===== -->
  <link name="caster_link">
    <visual>
      <geometry><sphere radius="${caster_radius}"/></geometry>
      <material name="dark"/>
    </visual>
    <collision>
      <geometry><sphere radius="${caster_radius}"/></geometry>
    </collision>
    <xacro:inertial_sphere mass="0.05" radius="${caster_radius}">
      <origin xyz="0 0 0" rpy="0 0 0"/>
    </xacro:inertial_sphere>
  </link>

  <joint name="caster_joint" type="fixed">
    <parent link="base_link"/>
    <child  link="caster_link"/>
    <origin xyz="${base_length/2 - 0.04} 0 ${-base_height/2 - wheel_radius + caster_radius}"
            rpy="0 0 0"/>
  </joint>

  <!-- ===== 雷達：昨天手打的那行 static_transform_publisher，今天由這段取代 ===== -->
  <link name="laser_link">
    <visual>
      <geometry><cylinder radius="0.035" length="0.04"/></geometry>
      <material name="red"/>
    </visual>
    <collision>
      <geometry><cylinder radius="0.035" length="0.04"/></geometry>
    </collision>
    <xacro:inertial_cylinder mass="0.15" length="0.04" radius="0.035">
      <origin xyz="0 0 0" rpy="0 0 0"/>
    </xacro:inertial_cylinder>
  </link>

  <joint name="laser_joint" type="fixed">
    <parent link="base_link"/>
    <child  link="laser_link"/>
    <origin xyz="0.10 0 ${base_height/2 + 0.02}" rpy="0 0 0"/>
  </joint>

</robot>

5-4　launch/display.launch.py

#!/usr/bin/env python3
import os
from ament_index_python.packages import get_package_share_directory
from launch import LaunchDescription
from launch.actions import DeclareLaunchArgument
from launch.substitutions import Command, LaunchConfiguration
from launch_ros.actions import Node
from launch_ros.parameter_descriptions import ParameterValue


def generate_launch_description():
    pkg = get_package_share_directory('my_robot_description')
    xacro_file = os.path.join(pkg, 'urdf', 'my_robot.urdf.xacro')
    rviz_cfg = os.path.join(pkg, 'rviz', 'display.rviz')

    gui_arg = DeclareLaunchArgument(
        'gui', default_value='true',
        description='是否開啟 joint_state_publisher_gui 滑桿')

    # Command(...) 會在啟動時執行 `xacro 檔案`，把展開結果當成字串
    # ParameterValue(..., value_type=str) 這層「一定要加」，
    # 否則 launch 會把那串 XML 猜成別的型別而報錯
    robot_description = ParameterValue(
        Command(['xacro ', xacro_file]), value_type=str)

    return LaunchDescription([
        gui_arg,

        Node(
            package='robot_state_publisher',
            executable='robot_state_publisher',
            name='robot_state_publisher',
            output='screen',
            parameters=[{'robot_description': robot_description}],
        ),

        # 開發階段用 GUI 拉滑桿假裝馬達回報角度
        Node(
            package='joint_state_publisher_gui',
            executable='joint_state_publisher_gui',
            name='joint_state_publisher_gui',
            condition=None,   # 想做開關可改用 IfCondition(LaunchConfiguration('gui'))
        ),

        Node(
            package='rviz2',
            executable='rviz2',
            name='rviz2',
            output='screen',
            arguments=['-d', rviz_cfg] if os.path.exists(rviz_cfg) else [],
        ),
    ])

  • tf2_echo base_link laser_link 的數值與你 URDF 裡寫的一致
  • 你能不看筆記說出 joint 的 origin 與 visual 的 origin 的差別，並各舉一個症狀

9. 🎓 助教筆記：Day 6 學生最會卡的地方

卡點 1：rviz2 的 RobotModel 一片空白 / 顯示 Status: Error

錯誤訊息：No transform from [base_link] to [map]，或 RobotModel 底下每個 link 都紅字。

依序檢查：
① Fixed Frame 是不是還停在預設的 map？（你根本沒有 map）改成 base_footprint
② RobotModel 的 Description Topic 有沒有設成 /robot_description？ROS2 改用 topic 傳 URDF，很多舊教學還在教 parameter，學生照著做一定卡
③ ros2 topic echo /robot_description --once 有沒有東西？沒有代表 robot_state_publisher 沒起來

卡點 2：Invalid parameter type / launch 直接崩潰

錯誤訊息：InvalidParameterTypeException: Wrong parameter type, parameter {robot_description} is of type {string}, setting it to {bool} is not allowed，或 Failed to parse the value as YAML

原因：launch 檔裡少了 ParameterValue(Command([...]), value_type=str) 這層包裝。launch 拿到那串 XML 後會嘗試自動判斷型別，判斷錯就炸。

解法：一律用
ParameterValue(Command(['xacro ', xacro_file]), value_type=str)
注意 'xacro ' 後面那個空格，少了它會變成 xacro/path/to/file，找不到指令。這個空格坑到過非常多人。

卡點 3：輪子躺平 / 車體歪掉 / 零件飛到旁邊

快速判斷法（教學生這樣自我診斷）：
・零件位置錯 → 看 joint 的 origin xyz
・零件朝向錯 → 看 joint 的 origin rpy（輪子需要 rpy="-1.5708 0 0"）
・零件位置對但形狀偏移 → 看 visual 的 origin
・關節轉的方向不對 → 看 <axis>（它是在子 link 自己的座標系裡定義的，不是父的）

診斷技巧：在 rviz 打開 TF 顯示（Show Axes），紅=x 綠=y 藍=z。看座標軸比看模型準確得多。

卡點 4：xacro 展開失敗

常見錯誤訊息與對應原因：
XacroException: undefined local: 'wheel_radius' → property 沒定義，或 include 的檔案沒載入
Invalid parameter "reflect" → 呼叫巨集時參數少給或名字打錯
XML parse error: mismatched tag → 標籤沒關（最常見是複製貼上時漏了 </link>）
No such file or directory: $(find ...) → package 沒 build 或 CMakeLists 沒 install 那個資料夾

SOP：一律先 xacro 檔案 > /tmp/out.urdf，它會直接給你行號。不要在 launch 裡除錯 xacro，錯誤訊息會被包三層看不懂。

卡點 5：改了 URDF 但畫面沒變

原因：URDF 是被 install 到 install/…/share/ 的，改 src/ 底下的原始檔沒有用。

解法：重 colcon build。
助教小技巧：教學生用 colcon build --symlink-install，這樣 src/ 的 urdf 改了會即時反映（因為裝的是符號連結），開發時省下大量重編時間。但要提醒：這招對自訂 msg 無效（Day 4 講過的）。

卡點 6：mesh（.stl / .dae）載入失敗

錯誤訊息：Could not load resource [package://my_robot_description/meshes/base.stl]: Unable to open file

三個原因：
① CMakeLists 的 install 沒有加 meshes 資料夾
② 路徑寫成相對路徑，必須用 package://套件名/meshes/xxx.stl
③ 單位問題：CAD 匯出常是公釐，URDF 一律用公尺。學生的模型大 1000 倍時，rviz 會顯示一片藍色（你在模型內部）→ 用 <mesh ... scale="0.001 0.001 0.001"/> 或匯出時就改單位。

本課程建議：教學階段一律用基本幾何體（box/cylinder/sphere），不要用 mesh。等 Day 21 做手臂專案再引入。

卡點 7：「為什麼要有 base_footprint？base_link 不夠嗎」

標準回答：「base_link 是車體中心，離地有一段高度。但導航演算法關心的是機器人在地面上佔了哪個位置——它在做 2D 的路徑規劃。base_footprint 就是 base_link 在地面的投影點，z 永遠是 0。」

補充：這是 Nav2 的慣例（robot_base_frame 預設常設為 base_footprint）。Day 10 設定 Nav2 參數時會直接用到，今天先把這個 frame 建起來，之後省事。
