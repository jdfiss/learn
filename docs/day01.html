Week 1 · 起步2026-08-05（星期三）· Physical AI 助教特訓 Day 1 / 30

今日目標：今天結束時，你要有一台能用的 ROS2 開發機——終端機不再讓你害怕、ros2 指令打得出來、並且能用 turtlesim 親眼「看見」兩個程式之間的資料流動，還能解釋那些資料是怎麼跑的。

先講清楚：ROS2 到底是什麼

ROS 的全名是 Robot Operating System，但它不是作業系統——這是新手第一個誤解。你的作業系統還是 Ubuntu。

比喻：把機器人想成一間餐廳。廚房（馬達控制）、外場（感測器）、櫃檯（決策）各自是獨立的員工，各做各的事。ROS2 是這間餐廳的對講系統與出單機——它定義了「誰喊什麼、誰聽什麼、話怎麼傳」，但它自己不炒菜。

技術上的正確說法：ROS2 是一套中介軟體（middleware）+ 工具鏈 + 套件生態。底層通訊靠 DDS（Data Distribution Service），這是航太與國防用了很多年的工業標準——這也是為什麼 ROS2 開機後不需要像 ROS1 那樣先跑一個 roscore：DDS 讓節點自己在網路上「互相發現」。

版本鎖定，這 30 天都不要改
Ubuntu 22.04 LTS ＋ ROS2 Humble Hawksbill ＋ Python 3.10 ＋ Gazebo Classic 11。
原因：ROS2 每個版本綁定特定 Ubuntu 版本（Humble 只支援 22.04），第三方套件（Nav2、MoveIt2、TurtleBot3）的教學與相依也都以此為準。混版本是新手 90% 痛苦的來源，你身為助教更要能一眼認出學生是不是裝錯版本。

1. 上午：Linux 求生包

1-1　路徑：絕對路徑與相對路徑

Linux 的檔案系統是一棵樹，樹根是 /。沒有 C 槽 D 槽。

  • /　根目錄，所有東西的起點
  • ~　你的家目錄，實際上是 /home/你的帳號
  • .　目前目錄　..　上一層目錄
  • /opt/ros/humble/　等一下 ROS2 會裝在這裡（/opt 慣例上放「第三方大型套件」）
常見誤解：「我把檔案放桌面就好」。Linux 開發請一律把程式碼放在 ~/ 底下的自建目錄（例如 ~/ros2_ws）。路徑裡有中文或空白，之後 colcon build 會出現各種莫名其妙的錯誤。路徑只用英文、數字、底線。

1-2　20 個你今天就會用到的指令

# --- 移動與觀察 ---
pwd                     # 我現在在哪
ls -la                  # 列出所有檔案，含隱藏檔（開頭是 . 的）與權限
cd ~/ros2_ws            # 切換目錄
cd -                    # 回到上一個待過的目錄
tree -L 2               # 樹狀顯示兩層（沒有的話 sudo apt install tree）

# --- 檔案操作 ---
mkdir -p a/b/c          # -p = 中間層不存在就一起建
cp 來源 目的            # 複製；cp -r 是整個資料夾
mv 來源 目的            # 移動 / 改名（同一個指令）
rm 檔案                 # 刪除；rm -rf 資料夾 = 強制遞迴刪，打錯會哭
cat 檔案                # 整份印出來
less 檔案               # 分頁看（q 離開）
nano 檔案               # 最簡單的編輯器（Ctrl+O 存檔、Ctrl+X 離開）

# --- 找東西（助教最常用）---
grep -rn "關鍵字" .     # 在目前目錄底下遞迴搜尋含關鍵字的行，並顯示行號
find . -name "*.launch.py"
which ros2              # ros2 這個指令實際上是哪個檔案
history | grep colcon   # 我剛剛打過什麼 colcon 指令

# --- 系統與程序 ---
htop                    # 看 CPU / 記憶體（q 離開）
nvidia-smi              # 看 GPU 與驅動版本
ps aux | grep ros       # 有哪些 ros 相關程序還活著
kill -9 PID             # 砍掉卡死的程序
df -h                   # 磁碟還剩多少

1-3　三個必懂觀念

(a) 權限與 sudo

ls -la 看到的 -rw-r--r-- 分成三組：擁有者 / 群組 / 其他人，各自的讀(r)寫(w)執行(x)。sudo 是「以管理員身分執行這一行」。

鐵律：安裝系統套件用 sudo apt，但絕對不要用 sudo 跑 colcon build 或 ros2 run。一旦用了，build 產生的檔案會變成 root 擁有，之後你自己的帳號改不動，只能全部刪掉重來。這是學生第一週最常見的自殘方式之一。

(b) 環境變數與 source

它解決什麼問題：你打 ros2，電腦怎麼知道去哪裡找這支程式？答案是環境變數 PATH——一份「要去哪些資料夾找指令」的清單。

比喻：環境變數像是你交給助理的一張便條紙，上面寫「工具在這幾個抽屜、零件在那幾個櫃子」。source setup.bash 就是把新的抽屜位置寫上便條紙。

關鍵在於：便條紙是「每個終端機視窗各一張」。你在 A 視窗 source 過，B 視窗完全不知道。這解釋了 90% 的「我明明裝好了為什麼說找不到」。

# 看幾個之後天天要用的變數
printenv ROS_DISTRO          # humble
printenv AMENT_PREFIX_PATH   # ROS2 會去哪些地方找 package
printenv ROS_DOMAIN_ID       # 空的就是 0

# source 只影響「當下這個終端機」
source /opt/ros/humble/setup.bash

(c) ~/.bashrc

每次開新終端機，bash 會自動執行 ~/.bashrc。所以把常用的 source 寫進去，就不用每次手打。

常見誤解：「全部塞進 .bashrc 最方便」。前期可以，但等你有兩個以上 workspace（例如同時裝了 Nav2 教學版與自己的），自動 source 全部會造成環境污染——ROS2 會找到錯的那份 package，而且錯誤訊息完全不會告訴你原因。助教一定要會問：「你的 .bashrc 裡有幾行 source？貼給我看。」

2. 下午：安裝 ROS2 Humble

照官方步驟走。每一段我都說明它在做什麼——因為你之後要幫學生判斷卡在哪一步。

2-0　先確認你的機器

lsb_release -a          # 必須是 Ubuntu 22.04
python3 --version       # 必須是 3.10.x
nvidia-smi              # 有輸出代表 NVIDIA 驅動正常；沒有的話先裝驅動再說
如果 nvidia-smi 沒反應：ubuntu-drivers devices 看建議版本，再 sudo apt install nvidia-driver-535（或建議的版本），裝完要重開機。Day 20 的 Isaac Sim 完全依賴這個，今天就處理掉。

2-1　設定語系（避免之後中文亂碼）

locale                                  # 先看現況
sudo apt update && sudo apt install -y locales
sudo locale-gen en_US en_US.UTF-8
sudo update-locale LC_ALL=en_US.UTF-8 LANG=en_US.UTF-8
export LANG=en_US.UTF-8
locale                                  # 確認變成 UTF-8

2-2　加入 ROS2 的套件來源

# 開啟 universe 軟體庫（ROS2 的相依有些在這裡）
sudo apt install -y software-properties-common
sudo add-apt-repository universe

# 下載並安裝 ROS2 的 GPG 金鑰（用來驗證套件沒被竄改）
sudo apt update && sudo apt install -y curl
sudo curl -sSL https://raw.githubusercontent.com/ros/rosdistro/master/ros.key \
  -o /usr/share/keyrings/ros-archive-keyring.gpg

# 把 ROS2 的來源寫進 apt 的清單
echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/ros-archive-keyring.gpg] http://packages.ros.org/ros2/ubuntu $(. /etc/os-release && echo $UBUNTU_CODENAME) main" \
  | sudo tee /etc/apt/sources.list.d/ros2.list > /dev/null

這一步在做什麼：apt 預設只認得 Ubuntu 官方的軟體倉庫。上面三段是（1）開啟社群倉庫、（2）安裝一把「驗章用的公鑰」、（3）告訴 apt「還有一個叫 packages.ros.org 的倉庫，它的東西用剛剛那把鑰匙驗」。學生若跳過金鑰那步，下一步 apt update 就會噴 NO_PUBKEY。

2-3　安裝本體

sudo apt update
sudo apt upgrade -y                 # 建議先更新系統，避免相依衝突

# desktop 版：核心 + rviz2 + demo + turtlesim，一次到位
sudo apt install -y ros-humble-desktop

# 開發工具（colcon、rosdep 等等，之後每天都要用）
sudo apt install -y ros-dev-tools python3-colcon-common-extensions

ros-humble-desktop 約 2–3 GB，網路慢的話會跑很久，是正常的。

2-4　初始化 rosdep

sudo rosdep init        # 若說 already exists，代表做過了，直接跳下一行
rosdep update           # 這行「不要」加 sudo

rosdep 是什麼：一個「相依翻譯機」。package.xml 裡寫的是 ROS 的抽象名稱（例如 rclpy），rosdep 負責把它翻成當前系統該裝的實際 apt 套件名。日後在別人的 workspace 根目錄下 rosdep install --from-paths src -y --ignore-src，就會一次補齊所有缺的相依。

2-5　設定環境並驗證

# 寫進 .bashrc，以後開終端機自動生效
echo "source /opt/ros/humble/setup.bash" >> ~/.bashrc
source ~/.bashrc

# 驗證三連發
printenv ROS_DISTRO         # humble
ros2 --help                 # 有輸出就是裝好了
ros2 doctor                 # 環境健檢，有 warning 先讀懂再決定要不要理

2-6　最終驗證：跑官方 demo

開兩個終端機（快捷鍵 Ctrl+Alt+T）：

# 終端機 A
ros2 run demo_nodes_cpp talker

# 終端機 B
ros2 run demo_nodes_py listener

B 應該印出 I heard: [Hello World: 1]。看到這行，你的 ROS2 就活著了。注意這裡刻意一個是 C++、一個是 Python——它們能對話，正是因為中間隔著 DDS 這層標準。

3. 晚上：turtlesim 觀察資料流

turtlesim 是官方的教學玩具，但它的價值不在「好玩」，在於它是最小的完整 ROS2 系統：有節點、有 topic、有 service、有 parameter。今天請你用「看資料流」的心態玩它。

3-1　啟動

# 終端機 A：模擬視窗
ros2 run turtlesim turtlesim_node

# 終端機 B：鍵盤控制（游標放這個視窗才會動）
ros2 run turtlesim turtle_teleop_key

3-2　把資料流「挖」出來

# 開第三個終端機

ros2 node list                       # 有哪些節點在跑
ros2 node info /turtlesim            # 這個節點發什麼、收什麼、開了哪些服務

ros2 topic list                      # 有哪些 topic
ros2 topic list -t                   # 順便顯示每個 topic 的訊息型別

# 看實際資料在流什麼
ros2 topic echo /turtle1/cmd_vel     # 按鍵盤時這裡會噴出速度指令
ros2 topic echo /turtle1/pose        # 烏龜的位置，一直在更新

# 這個 topic 的訊息長什麼樣
ros2 interface show geometry_msgs/msg/Twist

# 發多快
ros2 topic hz /turtle1/pose          # 約 62 Hz

# 誰在發、誰在收
ros2 topic info /turtle1/cmd_vel --verbose

3-3　不用鍵盤，直接用指令開烏龜

# 發一次速度指令（--once）
ros2 topic pub --once /turtle1/cmd_vel geometry_msgs/msg/Twist \
  "{linear: {x: 2.0, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 1.8}}"

# 持續以 1 Hz 發（讓牠一直繞圈；Ctrl+C 停）
ros2 topic pub -r 1 /turtle1/cmd_vel geometry_msgs/msg/Twist \
  "{linear: {x: 2.0}, angular: {z: 1.8}}"
觀察重點：停止發佈後烏龜會停下來，因為 turtlesim 內建了「一段時間沒收到指令就停」的保護。真實機器人的底盤驅動也幾乎都有這個機制，叫 watchdog / command timeout。學生問「為什麼我一放開鍵盤車就停了」，答案就是這個，不是程式壞了。

3-4　Service 與 Parameter 初體驗（明天 Day 2 會展開）

# Service：呼叫一次、等回覆。生一隻新烏龜出來
ros2 service list
ros2 service type /spawn
ros2 service call /spawn turtlesim/srv/Spawn "{x: 2.0, y: 2.0, theta: 0.0, name: 'turtle2'}"

# Parameter：節點的旋鈕，可以即時改
ros2 param list
ros2 param get /turtlesim background_b
ros2 param set /turtlesim background_r 255    # 背景馬上變色

3-5　Remapping：同一支程式控制不同烏龜

# teleop 預設發到 /turtle1/cmd_vel，把它改導到 turtle2
ros2 run turtlesim turtle_teleop_key --ros-args \
  --remap /turtle1/cmd_vel:=/turtle2/cmd_vel

這是 ROS 最重要的設計哲學的第一次體現：程式不需要改一行、不需要重新編譯，只要換接線就能用在不同地方。Day 4 會正式講。

3-6　把資料流畫出來

rqt_graph

左上角把過濾條件從 Nodes only 改成 Nodes/Topics (all)，並取消勾選 Hide: Dead sinks / Leaf topics，你會看到橢圓（節點）與方框（topic）連成的圖。請截圖存起來——這張圖就是你未來對學生解釋「ROS 是什麼」的第一張投影片。

6. 🎓 助教筆記：Day 1 學生最會卡的地方

安裝日是整門課求助率最高的一天。你要能在 30 秒內分類問題。先背這句診斷開場白：「請你貼三樣東西給我：lsb_release -a、你剛剛打的完整指令、完整錯誤訊息。」

卡點 1：apt update 出現 GPG / NO_PUBKEY 錯誤

錯誤訊息：The following signatures couldn't be verified because the public key is not available: NO_PUBKEY F42ED6FBAB17C654

原因：金鑰那一步失敗或被跳過（常見於網路擋 raw.githubusercontent.com）。

診斷：ls -l /usr/share/keyrings/ros-archive-keyring.gpg（檔案在不在、大小是不是 0）

解法：重跑 curl 那一行；若下載到 0 bytes，代表網路被擋，改用手機熱點或校內鏡像站。

卡點 2：Unable to locate package ros-humble-desktop

三個可能，照順序問：
① Ubuntu 版本不是 22.04 →lsb_release -a（20.04 對應 Foxy、24.04 對應 Jazzy，裝不到 Humble 是正常的）
② 加完來源後忘了再 sudo apt update（最常見）
③ /etc/apt/sources.list.d/ros2.list 內容寫錯 → cat 出來看，裡面的 codename 應該是 jammy

卡點 3：ros2: command not found

診斷：ls /opt/ros/humble/ —— 有東西代表裝好了，只是沒 source；沒東西代表根本沒裝成功。

解法：source /opt/ros/humble/setup.bash。若已經寫進 .bashrc 卻還是不行，通常是（a）寫進去之後沒開新終端機，或（b）寫成了 setup.sh / 路徑打錯 → tail -5 ~/.bashrc 看實際內容。

助教話術：「你這個是『安裝問題』還是『環境問題』？先 ls /opt/ros/humble，這一行就能分家。」

卡點 4：turtlesim 視窗開不出來

錯誤訊息：qt.qpa.plugin: Could not load the Qt platform plugin "xcb" 或 Authorization required, but no authorization protocol specified

原因：沒有圖形介面環境。常見於（a）用 SSH 連遠端沒開 X11 forwarding、（b）用 WSL 但版本太舊沒有 WSLg、（c）跑在純 server 版 Ubuntu。

診斷：echo $DISPLAY（空的就是沒有 GUI）

解法：SSH 加 -X；WSL 請升級到 WSL2 + Windows 11（有 WSLg）。本課程強烈建議實體安裝 Ubuntu 或雙系統，因為 Day 20 的 Isaac Sim 需要真正的 GPU 直通，WSL 會很痛苦。這件事要在開課第一天就講清楚。

卡點 5：rosdep init 說 already exists

訊息：ERROR: default sources list file already exists

這不是錯誤，代表之前已經初始化過。直接跑 rosdep update 即可。
反過來，如果學生對 rosdep update 加了 sudo，會把快取寫到 root 的家目錄，之後自己的帳號讀不到 → rm -rf ~/.ros/rosdep 再不加 sudo 重跑。

卡點 6：兩個人的 topic 互相看到

症狀：教室裡學生的 ros2 topic list 出現同學的 topic，或烏龜莫名其妙自己動。

原因：DDS 預設在同網段自動發現，ROS_DOMAIN_ID 沒設就都是 0。

解法（開課第一天就要統一規定）： 

echo "export ROS_DOMAIN_ID=座號" >> ~/.bashrc   # 取 0–101
# 或直接關在本機，最省事
echo "export ROS_LOCALHOST_ONLY=1" >> ~/.bashrc
